# 一个对话管全部：Friday 当调度员（2026-10-22）

## 起因

用户并行 5 个任务时，得在 5 个任务之间来回切：每条任务一段会话、一个终端，哪个做完了、哪个在等自己、这句话该对谁说，都要用户自己分辨。偶尔把给 A 的指示敲进 B 的终端。发错不常见，但心智负担一直在，**而且这不是一个智能 agent 该有的体验**：上下文本该握在 Friday 手里，不该由用户管窗口和路由。

现状里这件事在结构上就做不到：`terminal_say`、`task_update`、`task_approve`、`task_reject` 都只认「当前会话绑着的那条任务」（`tools.ts` 的 `boundTask` / `boundJob`），顶栏那段自由会话分发不了；`routeCandidates` 还特意把任务会话排除在外。用户想对哪条任务说话，只能先切到那条任务。

## 用户定的

- **你只在两个点出现：开工前的方案评审、做完后的验收。** 要拍板的事在方案评审里定完。**中间不中断**：执行时 Claude 碰到方案没覆盖的，按知识库和惯例自己定，接着做，在交付报告里写明「这里我替你定了 X」。
- **以后的任务都由 Friday 自己开工做，你可以随时干预。**
- **每条任务的会话不留**，只有一个主对话。**终端要能看到、能随时干预**：任务详情就是终端，你可以直接在里面打字。
- **Friday 能在对话里修改项目知识库**，你直接纠正它。
- **Friday 自己管理自己**：页面上能做的事，对话里都能做；要动代码的，不用你再去 Claude Code 里改 Friday，Friday 自己在 `friday` 项目上开任务。

## 目标

1. 一个主对话，Friday 根据任务板和知识库判断你在说哪件事，替你转给对应的任务或终端；判断不了就反问，不猜。
2. Friday 主动把需要你的事分成两类告诉你：**方案待审**、**待验收**。别的事不刷屏。
3. Friday 起的代码任务，中途能插话：在主对话里说，或者直接在终端里打字。
4. 页面上能做的配置，对话里都能做。超出配置范围的行为改动，Friday 当成 `friday` 项目上的普通任务去做。

## 非目标

- 不去掉终端。终端仍是任务详情的主体。
- HUD（呼出模式）不动。
- 定时任务的 friday 执行方会话不并进主对话，照旧独立。
- 后台只读的 `claude -p`（Slack 查询、理解卡建卡、知识库冷启动）不改成交互式，它们本来就不需要插话。
- 不做 Friday 自己合并、自己重启、自己重新打包。

## 反目标（技术上能跑，但做成这样就算失败）

- Friday 把你的话转错了任务，**而你看不出来**。每次转达都要在主对话里留一行「→ 已转给 #12 …：…」。
- 主对话变成通知流水账，每个终端每轮的进展都往里刷。
- 为了「不中断」，Claude 碰到大事也闷头自己定。方案没覆盖、**又会影响别人**的情况（改接口约定、动公共组件、碰远端数据）仍然要停下来，标「卡住」进你的队列。
- Friday 通过改自己的代码绕过守卫或权限分级。

## 依赖

**理解卡**（`feat/brief-card`，计划 `docs/superpowers/plans/2026-10-22-brief-card.md`，已做到 Task 5「需求门禁，和缺陷共用并发 1」，未合进 main）就是这里的「方案评审」：`brief_approve` 待审动作（方案看过，开工）、打回重建、按项目 `方案送审` 档位决定要不要审。本稿第四块（统一开工）要等它合进来；第一到三块不依赖它。

## 一、Friday 起的代码任务改成可插话

### 现状

自主任务在 tmux 里跑 `claude -p --model opus …`（`runner.ts:252`），一次跑到底，**中途敲不进话**。`friday_done` 后进程自己退出；`onJobExit` 兜底处理没写报告的情况。PreToolUse 已经对 `AskUserQuestion|ExitPlanMode` 回 deny（「这是无人值守的自主任务，没人能回答…」，`runner.ts:145`），所以「中间不中断」在提问这一层已经成立。

### 改成

代码任务（`startAutonomousJob`、`runInSession` 起的那次、`handToStorySession` 的 headless 接回）在 tmux 里跑**交互式** `claude`：

- 显式传 `--model opus`（`HEADLESS_MODEL`）。交互式现在不传 model，会继承用户的默认值，那就是 $4.46 那个坑。
- 守卫 hook 照挂：保护分支守卫、AskUserQuestion deny、`friday_done` 等桥接工具和提示词都不变。deny 的理由改成「按方案和知识库自己定，写进交付报告的『替你定了』；影响别人的（接口约定、公共组件、远端数据）调 `friday_blocked`」。
- 开场任务作为第一句传进去，和交互式终端现在的做法一样。
- **交付以 `friday_done` 为准，不看进程退出。** 进程交付后不退出，留着供你追问。
- **Claude 停了但没交付**（Stop hook 到了，这一轮既没有 `friday_done` 也没有 `friday_blocked`）：Friday 自动敲一句「继续；做完调 friday_done，卡住调 friday_blocked」，最多一次。第二次还是这样就标 blocked，写「停下来了没交付，看终端」。原来进程退出才触发的 `onJobExit` 兜底逻辑（`no_report`）改到这里。**只管 Friday 发起的轮次**：开场、催促、打回续跑、主对话转达。你自己在终端里打字问的那一轮，Claude 答完不调 `friday_done` 是正常的，不催（按 `UserPromptSubmit` 记下的最后一次输入是谁发起的来区分：`terminal_inputs` 里有记录的是 Friday 敲的，没有的是你打的）。
- 会话的 `kind` 还是 `autonomous`（归 Friday 驾驶）。`isFridayRun`、autostart「根会话是你开的交互式就跳过」这些判断不变。
- `DeliveryReport` 加 `decisions: string[]`（替你定了什么），交付消息和任务卡上都展示。

### 并发名额、轮次和账本

进程不退出以后，「job 还在 running」不能再当成「占着名额」。

- **名额**：任务进 review（交付）、blocked、done / ignored 就释放，进程活不活都不管。`runningAutonomous` 改成数「Friday 驾驶、任务状态是 processing」的根任务，不再看 `job.status`。
- **打回 = 续跑**：`rejectTask` 带原因时，任务的会话里 Claude 还活着，就把「上一轮被打回：原因」敲进去开下一轮，任务回到 processing（重新占名额，你点的不受名额限制）；Claude 已退出就 `resumeInSession` 接回再敲。
- **runs 一轮一行**：同一个 job 的每次交付都记一行，id 是 `<jobId>#<序号>`，沿用交互式轮次 `jobId#随机` 的做法。第一轮的 trigger 照旧（autostart / retry / approve / schedule），之后的轮次 trigger 记 `rejected`（打回续跑）或 `followup`（你追问后它又交付了一次）。成本记相对上一轮的增量（交互式轮次已经这么算）。结局（`merged_*` / `rejected` / `closed_unverified`）记在**最后一轮**那一行上；被打回的那一轮记 `rejected` 带原因，学手册照样能用到。`onJobExit` 只在进程真退出时（会话被关、Claude 崩了）收尾没交付的那一轮。
- **测试中需求的缺陷交接也在这一块做**：`handToStorySession` 现在对「自主会话活着」是「不接，等它退出」。需求会话改成不退出后，这条路会永远交不进去，所以这一块里就改成「Friday 驾驶的会话、Claude 活着、没在干活（不在一轮里）→ 敲进去；在干活 → 等这一轮交付后再敲」。

### 干预

- **在终端里直接打字**：可以。守卫照挂，你打字不会解除守卫。`UserPromptSubmit` hook 照常记录输入。
- **在主对话里说**：走第二块的路由，`terminal_say` 敲进去。
- **「这条我来」**：写 `source.autostartOff`，任务以后不再自动续跑。终端照旧在，守卫不撤。要不带守卫的自由环境，用项目页的 Claude 终端。

### 「开始做」和「交给 Friday 改」合成一个「开工」

两个都改成 Friday 驾驶的会话（带守卫、可插话）。手动点「开工」等于跳过队列和门禁立刻开，不受并发名额限制（你点的就开）。会话工具 `task_start` 同理。

其他现在走 `startInteractiveJob` 的入口也一起改成 Friday 驾驶：`run_claude`、`POST /run`、「跑 <项目>」、HUD relay（只改它调用的后端，HUD 界面不动）、有人值守的定时任务（`attended` 以后只表示「到点发通知告诉你开了」）。你自己驾驶、不带守卫的终端只剩项目页那一个入口。`startInteractiveJob` 只剩项目页在用。

### 并发

现在并发是 1（`runningAutonomous`）。用户实际在并行 5 件，所以改成设置项 `settings.autonomousConcurrency`，**默认 3（我的决定）**，对话里能调。总开关 `settings.autonomous` 的默认值改成开（用户定的：以后都由 Friday 开工）。已经存了 `false` 的不动，在主对话里提示一次「自己开工是关着的，要打开吗」。

## 二、主对话

### 一个对话

- 顶栏「会话」视图就是主对话，**只有一段**，跨天也是同一段。
- 底层 Claude session 不能无限续：**每天第一轮或累计超过 40 轮就换一个新的 Claude session**（我的决定，数字由实现者按实测上下文大小调）。界面上看还是同一段对话。连续性不靠聊天记录，靠每轮注入的任务板（见下文）。
- 去掉：`POST /route`（接旧会话 / 新开的判断）、`⌘⇧N` 新对话、「其实是新话题」。「···」→ 会话历史只列老的会话，只读。
- 任务不再自带会话：`createTask` 不再建会话、不再写 `source.conversationId`。老任务的会话数据留在库里不删。

### 消息挂任务

主对话里的消息可以带 `taskIds`：

- Friday 这一轮对哪条任务调了工具（`terminal_say`、`task_update`、`task_approve`、`task_reject`、`task_start`、`jobs_activity`、`task_get`），这一轮的用户消息和回答就挂上那些任务。
- Friday 主动发的消息（见下文）挂对应任务。

任务详情里的「相关对话」按 `taskIds` 筛主对话，只读、折叠，老任务把它原来那段会话也列在下面。

### 任务代号

每条任务一个**稳定的短号** `#N`（新列 `tasks.seq`，自增，建了就不变）。列表、详情头、主对话里的「→ 已转给 #12」、Friday 的汇总都用它。你可以说「#12 收下」，也可以说「导出那个收下」，两种 Friday 都要认。

### 工具改成带 taskId

`terminal_say`、`task_update`、`task_approve`、`task_reject`、`task_start`、`jobs_activity` 加必填 `taskId`（`#N`、id 前 8 位、完整 id 都认）。`boundTask` / `boundJob` 删掉。`task_approve` 的「整句同意」闸门不变，而且要能看出是同意**这一条**：同一轮里提到两条待审的，必须点名。

### 路由规则（写进系统提示）

按顺序：

1. 你点了名（`#N`、标题里的词、项目名加功能名）。
2. 指代 Friday 上一条主动消息说的那件事（「收下」「打回，按钮颜色不对」）。
3. 用任务板和知识库对得上：功能名或别名命中、项目命中，**并且**只剩一条开着的任务。

对不上，或者有两条都像，就反问「你说的是 #12 导出还是 #15 筛选？」。每次转达或改卡都要在回答里写「→ #N 标题：做了什么」。

### 每轮注入的任务板

替换现在的 `taskBlock`（只注入当前绑定的那一条）。改成注入**所有开着的任务的一行摘要**：`#N · 项目 · 标题 · 阶段 · 状态（方案待审 / 在干 / 待验收 / 卡住 / 排队）· 等了多久`，并且**这一轮提到过、或上一条主动消息涉及的任务**给完整块（沿用 `contextFor`）。整块有字数上限，超了就按「需要你 > 在干 > 排队」截断。

### Friday 主动开口

只在三种情况往主对话发消息，**模板拼，不调模型**：

| 时机 | 内容 |
|---|---|
| 理解卡进入待审（`brief.review === "pending"`） | `#N 标题 · 方案待审` + 方案要点 + 「要你拍板的点」 |
| 交付（`friday_done`，以及 Slack 查询任务的回复草稿） | `#N 标题 · 待验收` + 概要 + 替你定了 + 请你验证 + 截图（现在 `postDelivery` 往任务会话写的那份，改成写进主对话） |
| 卡住（`friday_blocked`、上面说的「停了没交付」、准备段失败） | `#N 标题 · 卡住` + 原因 |

**离开回来的汇总**：工作台窗口重新聚焦时，如果离上次聚焦超过 15 分钟，并且这期间有新进入上面三种状态的任务，就发一条汇总，同样用模板拼：

```
离开这 32 分钟，3 件要你：
方案待审  #15 基金筛选面板 · 要你定：筛选条件放 URL 还是 store
待验收    #12 理财导出 · 类型检查和测试过了，2 张截图
卡住      #18 养牛缺陷 2531 · canary 上造数接口 500
还在干：#9 跑测试中，#21 排队
```

**另外几种要你定的事**也算「卡住」这一类，发主动消息，进「等你」栏的「卡住」组，每条写清楚要你说什么：intake 反问项目归属（原来写在任务会话里）、`reproject`「项目判错，要撤掉吗」、`discard_changes`「缺陷已关，撤掉改动吗」、`start_job` 开工审批、理解卡依赖等你确认「到了」。这些事很少发生，而且不处理就会一直卡着，所以都要发。

「干活中」「这轮说了什么」这类过程信息**不发**，你问「#9 到哪了」再用 `jobs_activity` 回答。系统通知照旧。

### 一段对话里的先来后到

- Friday 还在回的时候你又说了一句：**排队**，这一轮回完再接着处理，输入框照常能打字发送，排着的消息显示「排队中」，可以撤回。想打断就按 Esc 或点停止（同现在）。`/ask` 不再回 409，改成入队。
- 主动消息不进 Claude session，是 Friday 直接写进对话的消息（`kind: notice`）。生成中到了就插在正在流式输出的那条**之后**，界面上立刻可见；下一轮的任务板注入会带上它，Claude 能看到。

### 界面

- **会话视图**：左边是主对话。右边一栏窄的「等你」：方案待审 N、待验收 N、卡住 N、在干 N，每条一行（`#N` + 标题），点了跳到任务视图的那一条。
- **任务视图**：列表在右，按「方案待审 / 待验收 / 卡住 / 在干 / 排队 / 其他」分组。详情 = 终端，头部一条：`#N` 标题、状态、待审动作按钮（方案看过开工 / 收下合并 / 打回…，后果预览照旧）、「相关对话」折叠。**详情里没有输入框。** 原来弹窗底部、自主卡底部的会话组件删掉；「详情」弹窗里的统筹信息保留。
- 任务没开工、没终端时，详情显示理解卡（第四块之前显示现在的空态，但不带会话）。

## 三、对话里管自己

### 原则

**页面上能做的，对话里都能做**，分级和页面一致：可撤销的直接做，记账，`undo` 能撤；撤不回的要你在对话里整句点头（同 `handbook_apply` 的闸门）。每次改动都记下你那句原话（`evidence.quote`）。

### 补的工具

| 工具 | 管什么 | 分级 |
|---|---|---|
| `settings_get` / `settings_update` | 白名单：`autonomous`、`autonomousConcurrency`、`model`、`skills`、`skillList`、`okrWeekly`、`learnHistory`、`name`、`theme`。`hotkey` 不放（壳启动时才读） | 可撤销，`undo: restore_settings` 存旧值 |
| `project_update` | 项目登记的结构化字段：目录、别名、说明、保护分支、方案送审档位、环境 / 频道。不再让模型 `memory_write` 整篇重写 `projects.md` | 可撤销，存改前整份 |
| `rules_list` / `rule_update` / `rule_retire` | 手册规则逐条改措辞或退役（同 `PATCH /rules/:id`），退役必须带原因 | 可撤销 |
| `knowledge_update` | 改功能条目的名字、别名、位置、路径、负责人、摘要；合并两条（历史并到留下的那条、名字进别名）；把一条历史挪到另一个功能；删条目 | 可撤销，`undo: restore_features`（已有）。删条目现在页面上是不可撤销，这里改成可撤销 |
| `worktrees_leftover` / `worktree_remove` | 遗留 worktree 列表和清理（同设置页） | 撤不回，整句点头。有未提交改动的要再说一次 |

`knowledge_update` 的纠正要能挡住下次再学错：`learnFromTask` 遇到用户纠正过的字段（记一个 `features.corrected` 字段名列表），模型给出的不同值不覆盖。

### 要动代码的

你说的事超出上面这些工具能做的范围（比如「以后 X 的时候应该 Y」，而 Y 是一段新逻辑），Friday 就用 `task_add` 在 **`friday` 项目**上建一条任务：标题写你要的行为，理解里附上你的原话和它判断「配置调不了」的理由。之后走和别的项目一样的流程：理解卡 → 方案评审 → 开工 → 交付 → 你验收。

`friday` 项目的硬规则（不管项目档位怎么设）：

- **方案一律送审**。
- **合并一律由你来做**，Friday 不挂会自动执行的合并动作。
- 交付报告写明「要重启 Friday / 重新打包才生效」。

`friday` 没在 `projects.md` 注册的，第一次需要时 Friday 提示你登记（或用 `project_update` 帮你登记，你点头）。

## 四、统一开工（等理解卡合进来）

理解卡的门禁（计划 Task 5，已在分支上，和缺陷共用并发 1）只管需求。在它的基础上改：并发改用第一块的 `autonomousConcurrency` 和新的名额判据；**所有代码任务**都走同一条：有理解卡、`review` 是 `none` 或 `approved`、依赖齐、项目已定、阶段未开始、没挂问题、没写 `autostartOff`，并发没满就开。

- **缺陷也建理解卡**（我的决定）。10-21 设计稿的「缺陷挂在需求下、不建理解卡」那块（缺陷归属）还没做；在它落地之前，缺陷单独建理解卡，规模判 `small`，按项目档位，「大的」档免审。缺陷归属落地后，再按那份设计稿改。
- 口头 / Slack 落成的代码任务同样建理解卡。
- `intake` 的 start / confidence 门禁退役（10-21 设计稿已经这么定了），设置页的「把握门槛」随之删掉。
- 测试中需求的缺陷交接（`testingStoryBug` / `handToStorySession`）保留，活会话那条第一块已经改好；「已退出」那条改成用交互式 `--resume` 接回（同第一块），不再起 `-p`。

## 顺序与规模

四块各自能独立交付：

1. **可插话的代码任务**：runner 改启动方式、停了没交付的催一次、`decisions` 字段、开工入口全部改成 Friday 驾驶、并发设置与名额判据、打回续跑、runs 一轮一行、需求会话活着时缺陷敲进去。
2. **主对话**：消息挂任务、`#N`、工具带 taskId、注入任务板、主动消息和回来汇总、消息排队、两个视图改版、删任务会话和路由。改动最大的一块。
3. **对话里管自己**：五组工具、知识库纠正防回写、`friday` 项目规则。
4. **统一开工**：等 `feat/brief-card` 合进来。

建议顺序 1 → 2 → 3 → 4。3 和 2 互相不依赖，可以并行。

## 留给实现者

- 主对话 Claude session 的轮换阈值、任务板注入的字数上限。
- 「回来汇总」的触发判据细节（窗口聚焦事件已有 `POST /jobs/sweep` 那条路径可以借用）。
- `#N` 的回填方式（老任务按 `created_at` 顺序补号）。
- 「相关对话」的展示形式。
- 第一块里催一次之后的等待时长。

## 我替用户做的决定（请过目）

- 并发默认 3；`settings.autonomous` 默认改成开。
- 主对话底层每天或 40 轮换一次 Claude session。
- 主动消息和回来汇总用模板拼，不调模型。
- 用户在终端里打字不解除守卫；要不带守卫的环境去项目页。
- 「开始做」和「交给 Friday 改」合成一个「开工」，都由 Friday 驾驶；`run_claude`、`/run`、HUD relay、有人值守的定时任务也一样。
- 并发名额在交付 / 卡住 / 收工时释放，不看进程；打回自动在原终端续跑。
- runs 一轮交付一行，结局记在最后一轮。
- 「停了没交付就催」只管 Friday 发起的轮次，你自己在终端里问的不催。
- 项目归属、项目判错回退、缺陷关了撤改动、依赖到了这几种要你定的事，归进「卡住」，发主动消息。
- 主对话里 Friday 在回的时候你再说话：排队，不打断。
- 缺陷在缺陷归属落地前单独建理解卡。
- `friday` 项目方案一律送审、合并一律由用户做。
- 知识库删条目改成可撤销；用户纠正过的字段，收工学习时不覆盖。
